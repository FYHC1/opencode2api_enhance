# 路由机制说明（Route Modes）

> 本文档说明 opencode2api 统一网关的路由模式：**负载均衡（round_robin）**、**故障转移（failover）** 和 **默认模式（failover + 健康计数，推荐）**。
> 面向使用者与开发者，涵盖各模式的行为、参数与配置方式。

---

## 一、三种模式总览

| 模式 | 别名 | 核心思想 | 适用场景 |
|------|------|---------|---------|
| **负载均衡** | round_robin | 每次请求轮询分发到不同实例 | 节点都健康、希望均摊流量 |
| **故障转移** | failover | 锁一个实例用，失败才换下一个 | 默认的历史模式，简单直接 |
| **默认模式（推荐）** | failover + 健康计数 | 故障转移 + 超时检测 + 计数淘汰 | **生产推荐**，兼顾稳定与容错 |

---

## 二、负载均衡（round_robin）

### 行为
- 维护一个游标，**每次请求游标 +1**，请求分发到对应实例
- 跳过"临时不可用"的实例（见下）

### 优点
- 流量均匀分散到所有实例
- 没有"单点压力"

### 缺点
- 可能命中异常实例（健康度低/冷却中的节点轮到时仍会被尝试）
- 对"免费额度"型节点不友好（均匀轮询会让每个节点都快速消耗额度）

### 配置
```json
{ "route_mode": "round_robin" }
```

---

## 三、故障转移（failover）

### 行为
- 维护一个游标，**成功不动游标**，**失败才切换到下一个健康实例**
- 锁定一个实例持续使用，直到它出错

### 流程
```
实例1 可用 → 一直用
   ├─ 故障(429/401/5xx/连接失败) → 切换实例2
实例2 可用 → 一直用
   ... 直到最后一个 = 1 轮
```

### 优点
- 稳定：锁一个健康实例，减少无谓切换
- 简单：逻辑直白

### 缺点
- **没有超时检测**：如果实例"挂起"（连接建立了但迟迟不吐数据），会一直干等
- **没有健康记忆**：反复失败的实例会被反复尝试，浪费请求

### 配置
```json
{ "route_mode": "failover" }
```

---

## 四、默认模式（推荐）：failover + 健康计数

### 行为
在**故障转移**基础上，增加：
1. **超时检测**（首字 / 静默）
2. **故障计数**（跨轮累计，3 次淘汰）
3. **成功清零**（恢复健康）

### 完整流程
```
实例1 可用 → 一直用
   ├─ 故障(429/401/5xx/连接失败) → 计数+1 → 切换实例2
   ├─ 超过 X 秒无响应（一个字都没收到）→ 计数+1，错误"延迟>X s" → 切换实例2
   └─ 回复到一半，卡住超过 Y 秒 → 计数+1 → 切换实例2
实例2 可用 → 一直用 ... 直到最后一个 = 1 轮
```

### 健康计数规则
- **计数 +1**：每次故障/超时
- **满 3 次** → **停止该实例**（不从池中移除），把错误信息展示给用户
- **用户手动重启实例** → 计数清零（重新开始）
- **某轮正常** → 计数清零（后续异常从 1 重新计数）
- 计数**跨轮累计**（一轮 = 从实例1 依次用到最后一个实例）

### 时间参数（可配置）
| 参数 | 默认值 | 白话含义 |
|------|--------|---------|
| **首字超时（TTFT）** | 10s | 发请求后干等 X 秒一个字没收到 → 换实例 |
| **静默超时** | 5s | 回复到一半，卡住 Y 秒没新内容 → 换实例 |
| **总超时** | 不设 | 长任务不限制（避免掐断正常长回复） |

### 为什么推荐
- **稳定**（继承故障转移的"锁节点"）
- **不干等**（超时检测兜底）
- **自我修复**（计数淘汰坏实例 + 重启恢复）

### 配置
```json
{ "route_mode": "failover" }
```

> 注：默认模式当前仍使用 `failover` 作为 route_mode 值，健康计数逻辑作为附加层启用。

---

## 五、参数速查表

| 参数 | 默认值 | 说明 |
|------|--------|------|
| route_mode | `failover` | `failover` / `round_robin` |
| 首字超时 | 10s | 干等多久无响应就切换 |
| 静默超时 | 5s | 中间卡住多久就切换 |
| 坏池阈值 | 3 次 | 故障计数满几次停止实例 |
| 总超时 | 不设 | 长任务不限制 |
