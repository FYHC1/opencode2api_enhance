## 一、停止扫描机制确权（回答用户的并发疑问）

**扫描并发模型**（`core/manager/probe_run.go`）：
- `workers`（= scan_concurrency，默认 8）个 goroutine **并行**探测节点；
- 点击停止 → `RequestStop()` 置 `Stopping` 标志 → **所有 worker 同时收到**（已经是"并发停止"）；
- 停止的**瓶颈**：正在跑的 `probeNode` 阻塞无取消机制（最多 25s 超时），**无法被中断**。

**结论**：用户直觉"批量停止（并发）能加速"——**方向对，但机制上停止已是并发标志**；
真正拖慢停止的是"正在探测的节点无法中断"。要让"停止并发"有意义，必须先给
`probeNode` 加取消支持（停止时 kill 正在跑的探针进程，复用 runner.Kill），
`stop_scan_concurrency` 才有语义：**停止时并发中断探测进程的上限**（防一次性斩断 8 个的资源尖峰）。

**拍板项（N2 语义）**：
- `stop_scan_concurrency`（默认 4）= 停止时**并发中断正在探测进程的上限**；
- 实施须含：① `probeNode` 取消支持（context/kill）；② 停止流程按此并发度中断；③ 前端传参/配置生效。
- 若不做取消支持，则该配置**必须删除**（死配置误导用户）。

## 二、全局任务悬浮窗（右下角）

### 2.1 现状（已有资产）

`App.tsx:131-149` 已有**全局释放进度悬浮面板**：`fixed bottom-5 right-5 z-50 w-64`，
显示标题 + `done/total` + 红色进度条 + "已完成|正在释放，不影响你继续操作…"。
由 PoolPage `onRelease={setRelease}` 上报（一键释放全部/退出并释放共用）。

**问题**：此面板仅支持"释放实例"一种任务；扫描、停止扫描、批量启停、一键重启池、
订阅拉取等长操作**没有全局展示**——用户切走页面就看不到进度，只能留在原页等。

### 2.2 目标设计

**通用全局任务面板**（扩展现有 release 面板，兼容多任务）：

```
右下角悬浮（fixed bottom-5 right-5 z-50 w-72，可多条任务纵向堆叠）
┌─────────────────────────────────┐
│ 🟢 扫描节点          12/50   [✕] │  ← 标题 + done/total + 可关闭
│ ████████░░░░░░░░░░░░ (24%)       │  ← 进度条（Red/Teal 按任务类型）
│ 正在扫描，不影响你继续操作…        │
├─────────────────────────────────┤
│ ⚠ 停止扫描            3/8    [✕] │  ← 第二任务可同时显示
│ ████░░░░░░░░░░░░░░░░ (37%)       │
│ 正在停止，不影响你继续操作…        │
└─────────────────────────────────┘
```

- **多任务栈**：`tasks: [{id, type, title, done, total, busy}]`，多个长操作同时进行时
  纵向堆叠；每任务可单独关闭（✕ 隐藏，后台继续）。
- **任务类型**（type 决定进度条颜色 + 标题文案）：
  | type | 触发点 | 进度来源 | 颜色 |
  |---|---|---|---|
  | release | 一键释放全部 / 退出并释放（已有） | PoolPage `onRelease` | red |
  | scan | 节点扫描（新） | NodesPage 轮询 scan 进度（done=Current, total=Total） | teal |
  | stop-scan | 停止扫描（新） | NodesPage stopScan（done=已停数, total=正在探测数） | amber |
  | batch | 批量启停/测试（新） | PoolPage/InstancesPage 批量操作（done/total 分块） | teal |
  | restart | 一键重启实例池（新） | PoolPage doRestart（前后端调用，进度=阶段 1~N） | amber |
- **跨页常驻**：任务启动后全局可见，**用户可自由切换菜单**；完成/失败自动收起重置。
- **不打扰**：悬浮窗不拦截点击（`pointer-events` 仅面板自身）；失败时文案变红并在
  toast 提示；不自动弹到前台。

### 2.3 功能开发（文件级）

1. **`src/App.tsx`**：
   - `release` state 扩为通用 `tasks` 数组（兼容现有 `onRelease` prop 形态——
     新增 `onTask({id,type,title,done,total,active})`，`onRelease` 保留包装兼容池页现有调用）；
   - 渲染多任务悬浮栈；每任务 title/done/total/进度条/关闭按钮；
   - 类型→颜色/文案映射表。
2. **`src/pages/NodesPage.tsx`**：
   - 扫描中：轮询到的 `scan.progress`（Current/Total）上报 `onTask({type:'scan',...})`；
   - 停止中：上报 `stop-scan`（done=已停 worker 数，total=停止时探测中数——需后端
     `RequestStop` 返回当前探测中数量，或前端用"停止前 scan.Current + 剩余未处理数"估算）。
3. **`src/pages/PoolPage.tsx`**：
   - `doRestart`（一键重启）上报 `restart` 任务（阶段进度：停网关→停全部→释放端口→
     启成员→网关收尾，done=阶段序，total=阶段数）；
   - 批量启停/测试上报 `batch`（分块并发时 done/total，与一键释放同款分块上报）。
4. **`src/pages/InstancesPage.tsx`**（可选）：独享页批量操作同上报 `batch`。
5. **后端**（配合 stop-scan 进度）：`RequestStop` 返回 `stopping_count`（当前探测中
   节点数）与 `stopped_count`（已停）——或前端估算，二选一（建议后端给准确值）。

### 2.4 测试

- 多任务同时显示（scan + release 并存堆叠）；单任务关闭 ✕ 不影响其他任务与后台执行；
- 跨页常驻：任务启动后切菜单，悬浮窗仍显示且进度更新；
- 完成自动消失；失败文案变红 + toast；0/0 状态不崩溃。
- `npm run build` + tsc 全绿；`go test` 不受影响（后端改动处补单测）。

### 2.5 验证（需部署机/用户）

- 扫描 20 节点 → 切到统计页 → 悬浮窗持续显示 12/20 直到完成消失；
- 停止扫描 → 切页 → 悬浮窗显示停止进度 → 完成消失；
- 一键重启池 → 悬浮窗显示阶段进度；
- 多任务并存（扫描中同时批量释放）→ 两条堆叠互不干扰。

## 三、顺带盘点：其他可用全局悬浮窗的长操作（已确认清单）

| 操作 | 页面 | 现状 | 建议 |
|---|---|---|---|
| 一键释放全部 | 实例池 | ✅ 已有全局面板 | 并入通用面板（迁移） |
| 退出并释放 | 全局/设置 | ✅ 已有（复用 release 面板） | 并入通用面板 |
| **节点扫描** | 节点池 | ❌ 页面内进度条，切页不可见 | 新增 scan 任务 |
| **停止扫描** | 节点池 | ❌ 仅按钮态"正在停止" | 新增 stop-scan 任务 |
| **一键重启池** | 实例池 | ❌ 按钮"重启中…"，切页不可见 | 新增 restart 任务 |
| **批量启停/测试** | 实例池/独享 | ❌ 仅按钮忙态 | 新增 batch 任务 |
| 订阅拉取 | 节点池 | ❌ toast 一次性 | 🟡 可选（单条快，多条轮询时有用） |
| 探活（立即探活） | 实例池 | ❌ 页面内"探活中…" | 🟡 可选（通常 <10s） |

**推荐范围**：先做 release/scan/stop-scan/restart/batch 五种（核心长操作）；
订阅/探活视排期可选。
