# opencode2api 管理器修复说明

> 记录 2026-08-13 更新后"全部节点不可用"问题的根因分析、修复方案与一键启动使用说明。

---

## 一、问题现象

更新后，管理器里全部节点显示**不可用**；所有探测失败；实例无法创建/使用。
客户端调用 API 报错：

| 阶段 | 错误 |
|---|---|
| 端口配置错误 | `fetch failed; url=http://127.0.0.1:18080/v1/chat/completions` |
| 网关路由问题 | `upstream error` / `502` |

---

## 二、根因分析（证据链完整）

### 根因 1：管理器转换节点时丢失 ws Host 头（导致全部节点 403）

- 管理器 `opencode2api.exe` 把 Clash 订阅节点转成 sing-box 配置时，**硬编码输出** `transport: {"path": "/", "type": "ws"}`，丢掉了 `ws-opts.headers.Host`。
- 管理器 Clash 解析结构体只定义了扁平键 `json:"ws-headers"`，而订阅源数据是嵌套的 `ws-opts.headers.Host`（转换时读不到）。
- sing-box 发起 WS 升级时，HTTP Host 头会默认用**前置 IP**（如 `62.133.60.155`），Cloudflare 收到 `Host=IP` 无法按 hostname 路由 → 返回 **HTTP 403**。
- 实测复现：

| 请求 Host | 结果 |
|---|---|
| `Host = 前置IP` | **403** ❌ |
| `Host = q1.liudp.cc.cd` | **101/200** ✅ |

- 给 sing-box 配置补上 `"headers": {"Host": "q1.liudp.cc.cd"}` 后，代理实测 google / opencode.ai 全部 **200**。
- 管理器二进制无源码，无法直接修改生成逻辑；数据层修补（给 Clash profile 加扁平 `ws-headers`）实测无效。

### 根因 2：批量创建的实例未加入网关（导致 502 upstream error）

- 通过 API 批量创建实例后，实例**未加入网关**（UI 流程会自动调用 `join-gateway`）。
- 网关只能路由到已加入的实例；池质量不佳时退回"直连"节点，而直连节点配置有缺陷（socks5 地址为空）→ `502 upstream error` / `all models failed`。

### 根因 3：池质量探测超时过短（3 秒）

- `pool_probe_timeout_sec` 默认 **3 秒**，而 CDN 优选节点延迟 6~12 秒 → 探测几乎必超时 → 池质量 0 healthy → 网关 smart 路由退回直连。
- 已调至 **15 秒**。

### 根因 4：网关端口变更

- 网关端口为 **40080**（不是旧配置的 18080），客户端需更新。

## 三、修复方案（已部署）

### 交付文件

| 文件 | 作用 |
|---|---|
| `E:\AI\opencode2api\fix_ws_host.py` | **Host 头修复守护**：每 20ms 轮询 `%APPDATA%\opencode2api-manager\runtime\` 下所有 `singbox.json`（递归含探测/实例目录），检测 vless+ws 出站缺 `headers.Host` 时用 `tls.server_name` 自动注入（原子替换） |
| `E:\AI\opencode2api\start_all.py` | **一键拉起**：管理器就绪后自动启动网关 + 全部实例，按时间戳检测本次启动后仍报 403 的实例并逐个重启修复，最后验证网关 `/v1/models` |
| `E:\AI\opencode2api\launch_manager.vbs` | **启动器**：依次启动 守护脚本(隐藏) → 管理器 GUI → 一键拉起(隐藏) |
| `C:\Users\Administrator\Desktop\opencode2api.lnk` | 桌面快捷方式（指向启动器，图标沿用管理器） |

### fix_ws_host.py 关键设计

- **stat 变更检测**：每轮只 `os.stat`（mtime+size），文件变化才读+修补，保证 20ms 轮询不被阻塞（读+md5 全文件会拖慢到 200ms+，导致批量启动时丢配置窗口）。
- **生命周期**：管理器进程关闭约 20 秒后守护脚本自动退出（`tasklist` 检查每 100 次循环才做一次，避免阻塞轮询）。
- **启动宽限期**：首次见到管理器进程前不退出（防止冷启动时管理器加载慢导致误退出）。
- 日志：`%APPDATA%\opencode2api-manager\runtime\fix_ws_host.log`

### start_all.py 流程

```
等待管理器 API 就绪(90s) → 确保网关 → 批量启动实例 → 等待 35s
→ 按时间戳检测本次启动后仍有 403 的实例 → 逐个重启修复
→ 对未 Running 实例补一次重试 → 验证网关 /v1/models
```

> 说明：批量启动实例存在竞态（管理器写配置后立即拉起 sing-box，约半数读到未修补配置报 403），start_all.py 的"逐个重启"环节保证最终全部生效。日志：`runtime\start_all.log`

## 四、一键启动使用说明

### 启动

双击桌面 **`opencode2api.lnk`**（或 `E:\AI\opencode2api\launch_manager.vbs`）：

```
修复守护(隐藏) → 管理器 GUI → 自动拉起 34 实例 + 网关 → 校验修复 → 验证 API
```

完整启动约 **3 分半**（含实例逐个校验），完成后即可使用。

### 客户端配置

```
Base URL:  http://127.0.0.1:40080/v1
API Key:   sk-unified-local
```

### 注意事项

1. **必须用桌面快捷方式打开** —— 直接用 `opencode2api.exe` 打开不会启动修复守护和自动拉起，节点会再次不可用。
2. 无开机自启（按需求已取消）；**重启电脑后**双击快捷方式即可一键恢复。
3. 实例延迟 2~10 秒属 CDN 优选节点正常特性。
4. opencode.ai 免费模型上游约 30~40% 不稳定（偶发 503/超时），网关自动 failover；连续失败稍等重试即可。
5. 若管理器作者后续修复了该 bug（正确输出 Host 头），守护脚本可停用，不影响使用。

## 六、关键结论

- 更新后全部节点不可用的**直接原因**是管理器新版的 sing-box 配置生成逻辑丢失 ws Host 头 → Cloudflare 403。
- 已通过**守护脚本注入 Host 头**解决（代理层修复），并补齐**实例入网关**、**探测超时**、**网关端口**三个连带问题。
- 一键启动方案（快捷方式 → 启动器 → 守护 + 自动拉起 + 校验修复）已端到端验证可用。
