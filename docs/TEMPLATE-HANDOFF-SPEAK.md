**审查要求**：
- 独立审查，不修改任何文件，产出问题清单（按严重度标注 高/中/低，每条带文件:行、问题描述、建议修复）

## 使用要点

1. **先 bug 后 review**：修复是有明确验收的活，review 是开放探索——先修后审队列不堵。
2. **高优先模块放表格前两行**：用户天天用的核心路径（竞速/路由/探活）优先。
3. **V 系列参照**：`docs/REVIEW-V-CODE-REVIEW.md` 展示了完整的审查输出格式（结论/安全/逻辑问题分级/建议/总结）——同事可参照产出。
4. **审查与修复分离**：审查者只读不改（防自我验证盲区）；修复由实施者或另一个子代理做。
5. **验收闭环**：审查问题→修复→重跑（-race + build + 走查）→ 全部收敛才算完成。
