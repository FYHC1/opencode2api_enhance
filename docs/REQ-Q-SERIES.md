# Q 系列：开发模式快速调试反馈（2026-08-16）

> 用户走 `npm run tauri:dev` 开发模式快速调试时发现的两个行为问题。
> 本需求文档记录问题现象与用户明确的行为约定；实施已随 commit 落地。
> 实施状态：Q-1 ✅；Q-2 ✅（随本提交）。

## 问题清单

| # | 现象 | 正确行为（用户约定） |
|---|---|---|
| Q1 | 节点池→我的订阅→删除：删除行为不完整 | 如果存在使用中的实例，就主动停止；全部停止后，从实例池、独享中移除释放；最后把这个订阅对应的节点组整个从节点池中移除 |
| Q2 | 节点池→导入订阅→点击保存：节点获取到后还要手动刷新才在节点池显示 | 点击保存时，应在获取到节点时就立刻在节点池显示，无需再手动刷新。导入订阅只保留「导入节点池」一个去向（无入池/独享选项） |

## 实施约定

1. **Q1 删除订阅 = 后端原子完成**（不再依赖前端补刀分步释放）：
   - 顺序：先停止该分组使用中的实例（已停止幂等跳过）→ 全部停止后从注册表移除
     （实例池/独享一并释放，含网关同步）→ 删除订阅源 → **最后**清理订阅缓存中该分组节点。
   - 节点组是最后一步——任何一步失败都不会把节点组先清掉。
   - 前端只调一次删除，展示后端返回的已释放数量。
2. **Q2 保存后节点池自动刷新**：10s 看门狗超时不再丢弃真实请求——
   后台完成导入后前端自动 `loadNodes/loadSubs`，节点获取到即在节点池显示，无需手动刷新。
