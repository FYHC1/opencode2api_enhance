## 2. 节点池扫描停止后轮询自杀（🔴 缺陷）

**文件**：`src/pages/NodesPage.tsx`

**复现步骤**（用户提供）：
1. 勾选 100 个节点，开始扫描；
2. 扫描到 50 个时点击「停止扫描」（页面状态显示正常）；
3. 再随机勾选一部分节点，点击「扫描」；
4. **页面扫描进度条为 0，且没有任何扫描迹象**。

**根因**（代码级）：
`poll` 轮询循环在 `stopAckRef` 分支命中时 `return` 直接退出函数，
跳过了底部的 `setTimeout(poll, 800)` —— **轮询循环永久终止**。
之后再次 `startScan` 只拿到 scanStart 的初始响应（progress=0），
没有轮询推进 → 进度条永远 0，看似没扫描。

```js
// 现状（BUG）：stopAck 命中即 return，poll 死亡
if (stopAckRef.current) {
  if (p.status === 'stopping' || p.status === 'done') {
    stopAckRef.current = false
    setScanning(false)
    return                    // ← poll 循环在这里自杀
  }
}
```

**修复**：stopAck 分支不 return，跳过本次 setScan 但继续轮询：

```js
const poll = async () => {
  if (!alive) return
  try {
    const p = await api.scanStatus()
    if (!alive) return
    const prev = prevScanStatusRef.current
    prevScanStatusRef.current = p.status
    if (stopAckRef.current) {
      if (p.status === 'stopping' || p.status === 'done') {
        stopAckRef.current = false
        setScanning(false)
        // 不再 return —— 继续走底部 setTimeout(poll, 800) 保持轮询存活
      } else {
        setScan(p)
        setScanning(true)
      }
    } else {
      setScan(p)
      setScanning(p.status === 'running' || p.status === 'stopping')
      if (p.status === 'done' && prev === 'running') setShowResult(true)
    }
  } catch { /* ignore */ }
  if (alive) setTimeout(poll, 800)
}
```

**连带确认**：后端 `ScanController.Start` 对"扫描已在进行中"返回错误——停止后立刻再扫可能报错，
属预期语义；前端 poll 修复后，停止→再扫链路正常。

**测试**：
- 复现路径走查：勾 100 → 扫 → 停 → 再勾 → 扫，进度条正常推进、结果弹窗正常。
- 轮询在停止后仍存活（连续两次扫描均正常）。

**验证**：按上述步骤在浏览器走查；**验收：停止后再次扫描进度正常。**

## 3. 独享页轮询统一

**现状**：
- 实例池页：`setInterval(3000)` 静默轮询（网关状态/实例/质量分）。
- 独享页：加载一次后**手动刷新**（`InstancesPage.tsx` 注释：不自动轮询，由用户点刷新按钮手动刷新）。

**改动**：独享页加 3s 轻量轮询——只刷新列表与状态显示（**不做**进程点名检查
`CHECK_BATCH` 校正，避免频繁启动检查），保留手动刷新按钮做深度校正。

**目的**：两页刷新体验一致；实例状态变化（崩溃/停止）能自动反映。

**测试**：轮询静默不打扰（无 toast、无闪烁）；手动刷新仍可用；状态自动更新。

**验证**：独享页开启实例 → 手动 kill 进程 → 3s 内状态自动变"已停止"（无需点刷新）。

## 4. 日志页大列表性能

**现状**：`LogsPage.tsx` 每次 `getCallLog(5000)` 拉全量 + `visible.map` 全量渲染 → 日志多时 DOM 爆炸。

**改动（轻量方案，不引库）**：
1. **前端分页**：`visible` 过滤后按页切片（每页 100 条），底部「上一页/下一页 + 页码」；
   默认显示最新页。
2. **保持 5s 轮询**但拉取量可配（`call_log_max` 已有配置，默认 5000 → 可调 2000 减少传输）。
3. 可选：列表项 `React.memo` 减少重渲染。

**克制原则**：不做虚拟滚动库（引依赖违背轻量化），分页足够。

**测试**：5000+ 条日志渲染流畅；分页切换正确；轮询后停留当前页（不跳页）。

**验证**：构造 5000 条日志 → 页面滚动/翻页无卡顿。

## 5. 统计页迷你可视化（克制版）

**现状**：纯数字表格（按实例聚合 + 节点下钻 + 按天），无图表。

**改动（纯 CSS，不引图表库）**：
- 每实例行加**成功/失败迷你条形图**（CSS `flex` + 色块，如绿=成功/红=失败占比）；
- 按天视图加**请求量/成功率趋势条**（纯 CSS 柱状，复用现有 Card 组件）；
- 其余保持现状。

**测试**：`npm run build`；数据 0 值时条图不崩溃；百分比正确。

**验证**：统计页目视——条图随数据变化正确渲染，无库依赖。

## 6. 设置页定位（方向确认，不改动）

**用户定调**：设置菜单**只负责全局配置信息**（Clash 外部控制、数据清理、残留进程、二进制、
自启等）；各模块（独享/实例池/节点池/统计/日志）是**独立功能区**，功能就近放在各自页面——
**不把所有功能收拢到设置页**，降低用户使用难度。
- 撤销此前"性能参数/订阅回设置页"的归拢思路；
- 各页面已有入口（如实例池右上角参数弹窗、节点池订阅管理）**维持现状**。
