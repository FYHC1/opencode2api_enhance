# 常见问题（FAQ）

使用 opencode2api 过程中遇到的常见问题与解决方法。遇到问题先看这里，没有收录的欢迎提 Issue。

---

## 1. 报错 `400 ... max_tokens is too large: 393216. This model supports at most 131072 completion tokens`

**完整报错：**

```
400 Error from provider (Console): Upstream request failed: [bad_request]
bad request: max_tokens is too large: 393216. This model supports at most
131072 completion tokens.
```

在应用的「日志」菜单里，这类 400 错误显示为：

```
错误: upstream status 400: <nil>
token: 输入 0 / 输出 0 · 耗时 -
```

**报错含义：**

报错字面意思是请求的 `max_tokens`（393216）超过了模型上限（131072），但**这通常不是模型或参数配置的问题**，而是**实例构建/网络环境不对**导致的连锁反应。

**常见原因：**

1. **构建实例时系统代理没有开启**——实例走了错误的网络路径，上游返回异常
2. **节点有问题**——部分 cf 优选节点不稳定，也会触发类似报错

**解决办法：**

**① 快速尝试：**

1. 删除出问题的实例
2. 打开系统代理
3. 重新添加实例并激活

**② 完整步骤（彻底解决）：**

1. **完全退出** opencode2api 管理器
2. 软件启动前，**先启动 Clash 并打开系统代理**（全局 / 规则模式均可——总之先开启系统代理）
3. 在**代理开启的状态下**进行检查、添加实例等操作，然后启动实例，即可正常使用
4. 之后保持代理开启，**平时不要关闭**

**③ 以上都不行 → 节点问题：**

部分 cf 优选节点有问题。判断方法：换一个模型进行对话测试——如果**其他模型能通，只有 deepseek 报「超过最大 token」**，基本可断定是节点问题，换一个节点重试即可。

## 2. 「调用日志」页显示的节点端口比实例端口大 2000（如 44200 → 46200）

**这是设计行为，不是 bug。**

每个实例有两个端口：

| 端口 | 值 | 用途 |
|---|---|---|
| 实例 API 端口 | 44200（实例页显示、复制的 API 地址用这个） | opencode2api 进程监听 |
| sing-box SOCKS5 端口 | 44200 + 2000 = **46200** | 实例的代理出口（出站代理） |

统一网关路由时，实际连接的是每个实例的 **sing-box SOCKS5 端口（API 端口 + 2000）**，所以「调用日志」页的节点地址如实记录为 `127.0.0.1:46200` 这类端口。这样设计是为了让 sing-box 与 API 端口紧挨错开、互不冲突（2026-08-10 端口规划改为 +2000；更早版本为 +10000，旧文档/旧日志里出现 +10000 属历史遗留）。

**如何对应回实例？** 用日志里的端口减去 2000 即为该实例的 API 端口；或开启「节点前缀展示」后，流式回复会直接显示实例名。

## 3. 节点池「扫描 → 入池/独享」操作说明

**流程：**

1. 在「节点池」页勾选要测试的节点 → 右侧「扫描选中节点」按钮亮起。
2. 点击扫描 → 显示进度条（已扫描 n/m，百分比实时更新）。扫描为**并发执行**（默认最多 8 个 worker 同时测，各持独立端口与进程；端口不足时自动降级），比逐个测试快得多。
3. 扫描完成 → 自动弹出结果弹窗：
   - 右上角 ✕ 可关闭（关闭后可再次扫描重新弹出）。
   - 中央绿色加粗数字 = 可用节点数。
   - 下方两个按钮：
     - **【入池】**：可用节点全部添加为实例并标记加入统一网关（实例池）。
     - **【独享】**：可用节点全部添加为独享实例（一人一实例，不入池）。
4. 无论点哪个，都会**自动去重**：已添加为实例的节点会被跳过（已在实例中的节点复选框也处于禁用状态），不会产生重复实例。

**说明：**

- 去重依据节点名：同一节点只允许例化一次。
- 入池只打标记、不自动启动实例，启停由「实例池」页控制；独享实例在「独享」页管理。
- 若可用节点为 0，弹窗中的按钮禁用并提示「没有可用节点」，可调整节点后重新扫描。
